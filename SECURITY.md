# Security and privacy

This is a household application, not a hardened multi-tenant streaming service. The default installer listens only on localhost. Remote deployment requires HTTPS and an access layer appropriate for your users. Keep media-service administration and NAS administration private.

Never commit or share `.env`, service API keys, session secrets, backups, databases, private screenshots, inventories, or setup logs containing sensitive information. The app’s Settings integrations accept your own service credentials; no credentials are supplied with this project.

The starter Compose file mounts only its application data volume. Acquiring media, importing files, and expiring rentals require separately configured services. The optional storage dashboard is read-only; the optional rental lifecycle can remove eligible media via Radarr after expiry. Review configuration and backups before enabling either integration path.

If you find a vulnerability, do not disclose secrets or exploitation details in a public issue. Use GitHub’s private vulnerability reporting when enabled, or contact the maintainer privately through an available channel. No independent security audit is claimed.

## Guided service setup

Optional services use loopback ports and Forms authentication. New API keys are cryptographically generated by the installer, not recovered from existing installations. `.setup-private.json` contains entered service credentials and is excluded from Git and the Docker build context; treat it as a secret. Only the chosen empty local media folder is mounted into Sonarr/Radarr. The Docker prerequisite helper requires explicit consent, validates the downloaded installer signature, and leaves terms/UAC/restart decisions to the user. No public routing or acquisitions are enabled by setup.
